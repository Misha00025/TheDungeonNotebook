# Правила изменения API

При добавлении, изменении или удалении API campaign-service подготовка API Gateway входит в ту же работу/итерацию и критерии её готовности, а не откладывается в отдельную задачу.

Перед завершением изменения API:

- Сверьте действия HTTP-контроллеров с `../api-gateway/configs/routes.yaml` и добавьте, измените или удалите явные маршруты и методы Gateway.
- Удалите устаревшие прокси маршрутов этого сервиса; не оставляйте мёртвые legacy-маршруты.
- Сохраните путь, query, body, статусы, `Location` и `ProblemDetails`; не добавляйте случайные DTO-обёртки или инъекции параметров.
- Передавайте `X-Subject` только из проверенного контекста Gateway. Предметные права доступа проверяет campaign-service.
- Актуализируйте документацию сервиса в `docs/` и руководство Gateway в `../api-gateway/README.md` и `docs/gateway.md`.
- Добавьте или обновите unit-покрытие маршрутов и hooks Gateway, а также относящиеся к изменению unit-тесты и сборку обоих компонентов до фиксации работы.

Это правило относится к последующим изменениям API campaign-service; оно не задаёт общую политику развёртывания.
