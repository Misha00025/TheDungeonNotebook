# @tdn/campaign

Кампания — Module Federation remote, который монтирует Hub. У неё нет отдельного HTML-приложения или собственного bootstrap авторизации и сессии. Hub передаёт полный shared auth-контракт; сервисы кампании используют общий authenticated request transport.

Hub проверяет BFF session и наличие профиля TDN до показа маршрутов кампании. Вход в IdP и создание профиля TDN — отдельные шаги. Если профиля нет, Hub показывает `CompleteProfile` поверх текущего URL и после создания профиля продолжает исходный маршрут.

## Сборка и preview

Из корня репозитория запустите сборку remote в watch-режиме, а во втором терминале — статический preview:

```bash
npm --prefix apps/web run dev --workspace @tdn/campaign
npm --prefix apps/web run preview --workspace @tdn/campaign
npm --prefix apps/web run build --workspace @tdn/campaign
```

Для локальной разработки preview раздаёт federation assets на `http://localhost:3000`; это локальный preview port, не опубликованный Docker port. Production remote assets маршрутизирует отдельный Web proxy из runtime env; remote URL не вшивается в Hub build. Это не standalone интерфейс кампании. Hub локально запускается отдельно на `http://localhost:3004`, владеет BFF session, а runtime config генерируется Web proxy.

Общий transport отправляет cookie credentials и CSRF header BFF для unsafe запросов. Ошибочные API-запросы автоматически не повторяются. Выход инициируется shared auth-клиентом: он удаляет локальную BFF session, затем выполняет верхнеуровневый переход через одноразовую BFF logout-ссылку для OIDC logout в IdP. Успешный POST сам по себе не гарантирует, что браузер дошёл до IdP и завершил SSO. Подробности callback и настройки Keycloak — в [README BFF](../../../../apps/bff/web/README.md).

## Каталог кампании

В GM- и player-пространствах доступен общий каталог предметов и навыков кампании. Список показывает доступные пользователю определения, поддерживает локальный фильтр типа и поиск по названию, а группы отображаются иерархическим деревом. При открытии определения Web отдельно читает его метаданные и содержимое; автор может редактировать своё определение, а GM с правом управления — создавать определения и менять видимость.

GM также может редактировать общую схему типизированных атрибутов и конфигурацию групп. Схема сохраняет неактивные атрибуты и ключи вариантов; варианты групп и условия не раскрывают служебные идентификаторы в интерфейсе. Записи схемы и групп используют собственные серверные ревизии и явное восстановление после конфликтов или неизвестного результата записи. Каталог не включает управление ценой, экипировкой или автоматическими эффектами.
