# @tdn/campaign

Приложение «Кампания» — группы, персонажи, игра (текущий функционал).

## Статус: remote-приложение микрофронтендов

Кампания — **remote** в архитектуре микрофронтендов (Module Federation,
`@originjs/vite-plugin-federation`). Собирается и деплоится отдельно.

- **Хаб (host)** монтирует кампанию под префиксом `/campaign/*` (модуль
  `campaign/App`) и подгружает страницу «Главная» на общей вкладке «Главная»
  (модуль `campaign/Home`).
- **Маршрутизация — у кампании** (вложенные роутеры). Хаб знает только
  верхний уровень.
- **Сессия** оркеструет хаб и прокидывает её в remote через пропс `session`.
  При автономном запуске (без хаба) кампания грузит сессию из хранилища
  (fallback) — см. `src/session/SessionProvider.tsx`.
- **Собственной навигации/панели нет** — её передаёт хаб. Внутренняя
  навигация кампании относительна к её корню (см. `src/navigation.ts`).
- **Темы** владеет хаб; логика прогрузки тем в remote не заносится.

### Экспонируемые модули (vite.config.ts → federation.exposes)

- `./App` — всё приложение (монтируется хабом под `/campaign/*`).
- `./Home` — только страница «Главная» (общая вкладка хаба).

### Автономный запуск

```bash
npm run dev --workspace @tdn/campaign   # или: cd apps/campaign && npm run dev
```

Не весь функционал работает автономно (сессия грузится из хранилища).

### Сборка

```bash
npm run build --workspace @tdn/campaign
```

`build.target: 'esnext'` обязателен — remoteEntry.js генерируется с
top-level await.
