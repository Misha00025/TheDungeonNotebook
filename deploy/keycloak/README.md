# Keycloak: установка

При первом запуске Compose импортирует realm из комплекта.

## Зависимости

Нужны Linux, `sh`, coreutils, `awk`, `curl`, `openssl` и `iproute2` (`ip` используется для определения IPv4 основного интерфейса при публичной установке). Для запуска по умолчанию нужен Docker Compose v2. Установщик не устанавливает пакеты и не использует `sudo`.

## Запуск

Основной способ на чистой машине — перейти в каталог установки и выполнить:

```sh
curl -fsSLo setup-keycloak.sh https://raw.githubusercontent.com/Misha00025/TheDungeonNotebook/master/scripts/setup-keycloak.sh &&
sh setup-keycloak.sh
```

По умолчанию комплект скачивается, IPv4 определяется локальным запросом маршрута основного интерфейса (сетевой запрос для этого не выполняется) и запускается публичный HTTP на `0.0.0.0:8180`; адрес Admin Console: `http://<IP>:8180/admin/`. Домен и proxy не нужны. Используется IPv4 основного интерфейса, внешний NAT-IP не определяется. Установщик не меняет firewall, security groups или NAT; входящий TCP-порт `8180` должен быть разрешён. HTTP не шифрует пароли: используйте этот режим для тестов; доверенный TLS для постоянной эксплуатации настраивается отдельно. Core Keycloak может отдельно требовать HTTPS для realm `master` или Admin UI; установщик эту политику не меняет.

Из checkout репозитория рекомендуется отдельный каталог, чтобы не смешивать файлы Keycloak с файлами репозитория:

```sh
sh scripts/setup-keycloak.sh --directory ../keycloak
```

По умолчанию файлы установки размещаются в текущем каталоге: `.env`, realm import и темы; PostgreSQL хранит данные в `./data/postgres` (bind mount). `--directory PATH` выбирает другой каталог. Доступны также `--local` для HTTP только на loopback, `--no-start` для подготовки файлов без запуска, `--ref REF` для загрузки комплекта из указанной ветки/тега/commit и `--source-dir PATH` для локального комплекта. `--ref` и `--source-dir` взаимоисключающие. `--start` сохранён для совместимости; запуск теперь выполняется и без него.

Повторный запуск сохраняет существующий `.env`. Секреты в нём защищены правами `0600`; не публикуйте файл. Установщик останавливается при несовпадающих конфигурационных файлах, отсутствующем `.env` для существующей базы или старом `.env` без требуемых сетевых параметров; не удаляйте данные и восстановите исходный `.env` перед повтором. Режима принудительного сброса нет.

Временная bootstrap-учётная запись администратора имеет имя `admin`; пароль находится в локальном `.env`. При первой настройке вручную войдите в `master`, создайте нового администратора через **Users**, задайте credentials и назначьте роль через **Role mappings**. Проверьте вход новой учётной записью, затем удалите временного `admin`.

Установщик не перезаписывает существующие отличающиеся настройки и не имеет режима принудительной перезаписи. Он не изменяет SQL-данные приложения, BFF или Keycloak через API; автоматических действий в UI и настройки пользователей и ролей нет.

## Оформление входа

В комплект входят готовые файлы темы `themes/tdn`; установщик доставляет их, а Compose автоматически подключает каталог темы. Чтобы включить оформление, в своём realm (не `master`) выберите **Realm settings → Themes → Login theme → tdn → Save**. Доступны русские и английские подписи. Для русских форм при необходимости откройте **Realm settings → Localization**, установите **Internationalization enabled: On**, добавьте **ru** и **en** в **Supported locales**, задайте **Default locale: ru** и нажмите **Save**.

Для существующей установки запустите из каталога установки (подставив путь к checkout репозитория вместо `/path/to/TheDungeonNotebook`):

```sh
cp -R /path/to/TheDungeonNotebook/deploy/keycloak/themes .
```

В местном `docker-compose.yml` добавьте в volumes сервиса `keycloak` строку `./themes:/opt/keycloak/themes:ro`, если её ещё нет. Затем в каталоге установки выполните `docker compose up -d --no-deps keycloak` и выберите тему в UI. Установщик намеренно не перезаписывает отличающиеся существующие конфигурационные файлы; если Compose-конфигурация отличается, не следует просто повторно запускать установщик.

## Только логин и пароль

Регистрационный шаблон темы `tdn` явно выводит `username`, `password` и `password-confirm`. Профиль realm отдельно ограничивает приём других данных. Для нового realm, созданного импортом комплекта, профиль уже настроен: регистрация просит подтвердить тот же пароль — это не дополнительное персональное поле. Для существующей установки обновите файлы темы по инструкции выше и перезапустите Keycloak; комплект не обновляет активную установку автоматически.

Для существующего realm настройте профиль вручную: выберите свой realm → **Realm settings → User profile**. У `firstName` и `lastName` через меню строки выберите **Delete** (не удаляйте `username`). У `email` выберите **Edit**: **Required field: Off**, **Who can view: только admin**, **Who can edit: никто** (снимите `user` и `admin`), затем **Save**. Не удаляйте `email` из схемы: это вызовет ошибку проверки профиля. Установите **Unmanaged attributes: Disabled** и нажмите **Save**.

Затем откройте **Realm settings → Login** и установите **Login with email: Off**, **Email as username: Off**, **Verify email: Off**, **Forgot password: Off**, затем нажмите **Save**. Email остаётся служебным полем схемы, видимым администратору только для чтения; новые значения пользователем не собираются. Эти изменения не очищают уже сохранённые email или ФИО — при необходимости администратор удаляет старые значения отдельно.
