# Локальный Keycloak

Комплект подготавливает локальный контур Keycloak для разработки. Он работает только на этой машине и публикует порт `8180` на loopback-интерфейсе. При первом запуске Compose импортирует realm из файла комплекта.

## Зависимости

Для подготовки нужны Linux, POSIX `sh` (в том числе `dash`), `coreutils` (`mktemp`, `cmp`, `cp`, `cat`, `mkdir`, `stat`, `wc`, `chmod`, `rm`) и `awk`. Для загрузки комплекта нужны `curl`, для новых credentials — `openssl`. Docker Compose v2 нужен только при использовании `--start`. Установщик не устанавливает пакеты и не использует `sudo`.

## Запуск

Из checkout репозитория:

```sh
sh scripts/setup-keycloak.sh --start
```

Без `--start` скрипт только подготовит каталог. По умолчанию это `$HOME/apps/keycloack`. Параметр `--directory PATH` задаёт другой каталог. PostgreSQL хранит данные в `data/postgres` внутри папки установки; `--directory` меняет расположение вместе для конфигурации и данных.

Для локального набора файлов можно передать `--source-dir PATH`; для загрузки комплекта, включая тему tdn, с репозитория — `--ref REF`, например `--ref master`. Эти параметры взаимоисключающие. Указанный ref должен быть опубликованной веткой, тегом или commit: и установщик, и остальные файлы комплекта загружаются именно из него. Для воспроизводимого запуска вместо `master` можно указать полный SHA commit. Локальные непубликуемые изменения checkout удалённому установщику недоступны.

На чистой машине установщик можно скачать и запустить:

```sh
curl -fsSLo setup-keycloak.sh https://raw.githubusercontent.com/Misha00025/TheDungeonNotebook/master/scripts/setup-keycloak.sh &&
sh setup-keycloak.sh --ref master --start
```

`--start` после подготовки проверяет Compose-конфигурацию и запускает контейнеры с ожиданием healthcheck; без него Docker не вызывается.

Повторный запуск сохраняет существующие `.env` и совпадающие файлы. При конфликтующем конфигурационном файле установка останавливается без перезаписи. Если конфигурация уже существует, а `.env` утрачен, установщик отказывается генерировать новые пароли: восстановите исходный `.env` из защищённой резервной копии.

Файл `.env` содержит секреты и не должен публиковаться или добавляться в систему контроля версий. Случайный пароль PostgreSQL нужен для повторных запусков с той же базой данных и не является одноразовым. Временной является bootstrap-учётная запись администратора Keycloak. При первой настройке вручную войдите в `master`, создайте нового администратора через **Users**, задайте credentials и назначьте роль через **Role mappings**. Проверьте вход новой учётной записью, затем удалите временного `admin`. Запуск контейнеров сам по себе не означает, что сайт настроен.

Установщик не перезаписывает существующие отличающиеся настройки и не имеет режима принудительной перезаписи. Он не изменяет SQL-данные приложения, BFF или Keycloak через API; автоматических действий в UI и настройки пользователей и ролей нет.

## Оформление входа

В комплект входят готовые файлы темы `themes/tdn`; установщик доставляет их, а Compose автоматически подключает каталог темы. Чтобы включить оформление, в своём realm (не `master`) выберите **Realm settings → Themes → Login theme → tdn → Save**. Доступны русские и английские подписи. Для русских форм при необходимости откройте **Realm settings → Localization**, установите **Internationalization enabled: On**, добавьте **ru** и **en** в **Supported locales**, задайте **Default locale: ru** и нажмите **Save**.

Для существующей установки перенесите тему из checkout:

```sh
cp -R deploy/keycloak/themes ~/apps/keycloack/
```

В `~/apps/keycloack/docker-compose.yml` добавьте в volumes сервиса `keycloak` строку `./themes:/opt/keycloak/themes:ro`, если её ещё нет. Затем из `~/apps/keycloack` выполните `docker compose up -d --no-deps keycloak` и выберите тему в UI. Установщик намеренно не перезаписывает отличающиеся существующие конфигурационные файлы; если Compose-конфигурация отличается, не следует просто повторно запускать установщик.

## Только логин и пароль

Регистрационный шаблон темы `tdn` явно выводит `username`, `password` и `password-confirm`. Профиль realm отдельно ограничивает приём других данных. Для нового realm, созданного импортом комплекта, профиль уже настроен: регистрация просит подтвердить тот же пароль — это не дополнительное персональное поле. Для существующей установки обновите файлы темы по инструкции выше и перезапустите Keycloak; комплект не обновляет активную установку автоматически.

Для существующего realm настройте профиль вручную: выберите свой realm → **Realm settings → User profile**. У `firstName` и `lastName` через меню строки выберите **Delete** (не удаляйте `username`). У `email` выберите **Edit**: **Required field: Off**, **Who can view: только admin**, **Who can edit: никто** (снимите `user` и `admin`), затем **Save**. Не удаляйте `email` из схемы: это вызовет ошибку проверки профиля. Установите **Unmanaged attributes: Disabled** и нажмите **Save**.

Затем откройте **Realm settings → Login** и установите **Login with email: Off**, **Email as username: Off**, **Verify email: Off**, **Forgot password: Off**, затем нажмите **Save**. Email остаётся служебным полем схемы, видимым администратору только для чтения; новые значения пользователем не собираются. Эти изменения не очищают уже сохранённые email или ФИО — при необходимости администратор удаляет старые значения отдельно.
