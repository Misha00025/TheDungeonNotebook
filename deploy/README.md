# Развёртывание The Dungeon Notebook

Для установки выберите нужные области — Backend + BFF, Web и/или Keycloak — через установщик:

```sh
curl -fsSLo install.sh https://raw.githubusercontent.com/Misha00025/TheDungeonNotebook/master/deploy/install.sh && bash install.sh
```

Установщик автоматически получает согласованный checkout исходников и устанавливает выбранные новые области в `/opt/tdn`: `backend`, `web`, `keycloak`, меню `menu.sh` и отдельный checkout в `.sources`. Перед запуском нужны Bash 4.3+, coreutils, curl, Git, Docker Compose v2, OpenSSL и jq; Make нужен при выборе Backend или Web. Пакеты автоматически не устанавливаются. У пользователя должны быть права записи в `/opt/tdn`; установщик не запускает sudo и не меняет системные права.

Сначала показываются выбор областей, обязательные настройки только новых областей и итоговое подтверждение. После подтверждения установщик выводит обычный непрерывный журнал получения исходников, подготовки конфигурации, сборки, проверки и запуска; дополнительных вопросов нет. Не выбранные области не создаются и не запускаются. Стандартный корень установки — `/opt/tdn`.

При установке новые базы и пользователи инициализируются автоматически со штатными именами из шаблонов (`tdn_users`, `tdn_campaign`, `tdn_accounts`, `tdn-settings`, `tdn`, `tdn-schemas`); новые Compose projects получают имена `tdn-backend`, `tdn-web` и `tdn-keycloak`. Это параметры первоначальной установки, а не обычные runtime-настройки меню. Ротация credentials и миграция существующих баз требуют отдельного выполнения.

Пароли баз данных и служебные ключи новых Backend+BFF/Keycloak областей генерируются автоматически. OIDC использует один provider и единый набор настроек: внешний issuer вводится один раз вместе с audience, client ID и методом аутентификации. При выборе нового Keycloak локальный client и audience настраиваются автоматически. Client secret обязателен для PostBody/Basic и не задаётся для public client None. Конфигурации создаются до первого запуска; секретные `.env` и сгенерированные JSON-конфигурации защищены правами `0600`. Realm import содержит только Keycloak environment placeholder, не plaintext client secret, и читаем контейнером. Credentials остаются в локальных файлах; ротация уже выданных credentials не реализована.

Повторный запуск выбранной области с существующим Compose подключает её в конфигурацию меню без изменения `.env`, JSON, данных и запущенных сервисов. Если каталог содержит данные или файлы, но Compose отсутствует, установка останавливается и сохраняет содержимое. Уже существующий `menu.sh` не заменяется автоматически; его обновление — отдельное действие меню. Для управления запустите:

```sh
bash /opt/tdn/menu.sh
```

Меню также можно запустить отдельно и подключить существующие Compose-каталоги через управление конфигурацией. Оно показывает состояние и управляет update/restart/stop выбранных существующих сервисов. Путь checkout исходников хранится в служебной конфигурации меню и не задаётся через интерфейс.

Внешняя доступность адресов Keycloak, BFF и Web зависит от DNS, TLS, proxy и сетевой конфигурации оператора; установщик не создаёт ingress, не настраивает firewall и не меняет TLS validation.
